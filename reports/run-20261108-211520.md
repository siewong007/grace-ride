## Objective (this session)
Complete the bilingual error-message implementation so server error messages follow the user's configured language (`users.lang`), instead of being hardcoded 中文/English pairs. The `Lang`/`t()`/`users.lang` infrastructure was already in place; `error.rs` was the last holdout.

## Changes
- `backend/src/error.rs`: `Unauthorized`/`NotFound` now carry a resolved `String` message built by new helpers `unauthorized(lang)` / `not_found(lang)` (the zh/en pairs live once in `error.rs` via `t()`). `into_response` emits the carried message. `Db RowNotFound` / `Db other` / `Other` fall back to the app default locale (`zh`) because user context is unavailable at `?`-propagation time (documented limitation).
- `backend/src/auth.rs`: `CurrentUser::from_request_parts` resolves `accept_lang` from the `Accept-Language` header and uses `unauthorized(accept_lang)` for session failures (unauthenticated 401s).
- `backend/src/routes/auth.rs`: `invite_preview` / `invite_accept` use `not_found(lang)` (lang from `Accept-Language`).
- All route `AppError::NotFound` sites → `not_found(u.lang)` (events, files, admin, community, settlements, rides).
- `backend/src/util.rs`: `Lang` now derives `Serialize` so `CurrentUser` (which derives `Serialize`) can hold `lang`; added `use serde::Serialize`.
- `backend/src/routes/rides.rs`: `set_status` caller at the invite-return path now passes `u.lang`; other `set_status` callers already passed `u.lang`.
- `backend/src/routes/auth.rs`: fixed a local `let t = ... as u64` that shadowed the `t()` translation function in TOTP verify.
- `backend/migrations/0003_language.sql`: `ALTER TABLE users ADD COLUMN lang TEXT NOT NULL DEFAULT 'zh' CHECK (lang IN ('zh','en'))`.
- `PROGRESS.md`: state/test-results update.
